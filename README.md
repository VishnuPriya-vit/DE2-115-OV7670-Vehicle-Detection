# Real-Time Vehicle Detection on DE2-115 FPGA

This project implements real-time vehicle detection using an OV7670 camera and a Terasic DE2-115 FPGA board. The VGA monitor displays the live colour camera image with green detection boxes and status text.

The design combines background subtraction with reference-pattern matching. It is calibrated for the three vehicle classes represented by the supplied reference data; it is not a general-purpose detector. The reference set contains 59 views represented by 236 compact descriptors.

## Hardware

- Terasic DE2-115 board with Cyclone IV E EP4CE115F29C7
- OV7670 camera module, RGB565, without FIFO
- VGA monitor connected to the board's ADV7123 VGA output
- Quartus Prime Lite for FPGA compilation
- ModelSim Intel FPGA Edition or Icarus Verilog for simulation

The design is written in Verilog-2001 and uses inferred memories. It does not require PLL or generated IP files.

## Repository contents

- `vehicle_detector.qpf`, `vehicle_detector.qsf`, `vehicle_detector.sdc` — Quartus project, pin assignments, and timing constraints
- `rtl/` — top module, camera capture/configuration, detector, reference matcher, frame memory, and VGA display modules
- `sim/` — testbenches, simulation scripts, expected vectors, and verification notes
- `reference/` — reference descriptors, matching limits, source images, and manifests
- `tools/` — scripts used to generate references and simulation data
- `START_HERE.txt`, `TECHNICAL_NOTES.txt`, `WIRING.txt` — build notes, design details, and camera wiring

## Build in Quartus

1. Extract this repository and open `vehicle_detector.qpf` in Quartus Prime Lite.
2. Run **Processing → Start Compilation**.
3. Check that compilation, fitting, and timing analysis complete successfully.
4. Program the generated `output_files/vehicle_detector.sof` to the board using USB-Blaster.

The `.sof` programming file is generated by Quartus and is not included in this source package.

## Run the simulations

From the `sim/` directory:

- ModelSim: run `do run.do`
- Icarus Verilog: run `sh run_iverilog.sh`

The regression should report 12 PASS lines and no FAIL lines. See `sim/VERIFICATION.txt` for the test descriptions. A passing simulation does not replace compiling and testing the design on the target FPGA.

## Camera wiring

Connect the OV7670 signals to the DE2-115 FPGA package pins listed below. The full table is in `WIRING.txt`.

| OV7670 signal | FPGA package pin |
|---|---|
| D0–D7 | AB22, AC15, AB21, Y17, AC21, Y16, AD21, AE16 |
| PCLK | AD15 |
| HREF | AE15 |
| VSYNC | AC19 |
| XCLK | AF16 |
| SCL | AD19 |
| SDA | AF15 |
| RESET | AF24 |
| PWDN | AE21 |

Use the board's 3.3 V supply and ground for the camera. The camera I/O bank must use 3.3 V. Do not connect the camera's supply input to 5 V. Switch off board power before changing wiring.

## Starting the design

Keep the camera and scene fixed while the FPGA learns the empty background after startup. If the camera or background is moved, remove objects from the view, hold KEY1 for about two seconds to relearn the background, then wait about one second before testing again. KEY1 updates the background; it does not add reference views.

## Scope and limitations

Detection depends on the supplied reference patterns, camera view, lighting, object size, and background. Similar colours or patterns may cause false detections, and unfamiliar views may be missed. The included photographs and simulated scenes are calibration and regression data, not a guarantee of accuracy in every environment. Recompile and test on the actual DE2-115 and camera before demonstrating the project.
